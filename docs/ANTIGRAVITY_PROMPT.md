# Gemini Antigravity 개발 지시 프롬프트 — luxuryRental

당신은 프런트엔드·Node.js 백엔드·ERP 도메인·모바일 UI/UX·브랜드 모션을 담당하는 시니어 풀스택 개발자입니다.

## 작업 기준
첨부된 `luxuryRental-starter` 저장소를 **실제 파일을 열어 분석한 다음**, 기존 사이트 골격·메뉴·기능·브랜드명을 불필요하게 바꾸지 않고 고도화하세요. 원본 프로젝트가 별도로 제공되면 원본의 파일 구조, 라우트, DB, 기존 UI와 기능을 먼저 비교하여 손실 없는 단계별 병합 계획을 세우세요. 다른 프로젝트 이름으로 리브랜딩하지 마세요.

## 반드시 구현할 결과
1. **고급스러운 모바일 웹**: 360/375/390/430px 기준, 반응형 태블릿과 데스크톱. 화이트/크림/다크 잉크/샴페인 골드의 미니멀한 에디토리얼 레이아웃. 모바일 하단 5개 탭과 스티키 CTA. 기존 Tailwind CSS v4 준수.
2. **브랜딩**: `LR` 모노그램 각인(emboss/engrave) 디자인을 벡터 SVG로 유지. `luxuryRental` 워드마크, 시작 스플래시, PWA 아이콘, 관리자 로고 통일. 실제 타사 로고·상표 복제 금지. 스플래시는 OS 설치 아이콘과 런칭 전용 인앱 화면을 구분.
3. **제품/구매**: 상품 컬렉션·브랜드·상태등급·상세·검색·정렬·위시리스트·구매 체크아웃·고객 마이페이지 구현. 스켈레톤, 에러, 빈 결과, 서버 실패 처리.
4. **렌탈**: 고객이 대여 기간·가격·보증금·배송/반납 조건을 확인. 캘린더에서 개별 실물의 가용성 조회, 중복 예약 방지, 반납/연장, 구매 전환 여부를 정책에 따라 처리. 보증금·보험·훼손·연체 정책을 UI에 표시하며 실제 사용 전 검증.
5. **ERP**: 단순 통계페이지가 아니라 상품(Product)↔실물(Unit)↔렌탈/주문(Order/Rental)↔재고 이벤트(InventoryEvent) 연결. 관리자 RBAC, SKU/시리얼/바코드, 상태(준비/예약/출고/반납/검수/세탁/수선/판매), 매출/정산, 배송관리, CMS/에디토리얼 관리. PostgreSQL + ORM(Prisma 등), 강한 일관성과 감사 로그를 운영 확장.
6. **Node.js API**: TypeScript 기반 NestJS 또는 Fastify/Express로 확장 가능. 입력 스키마 검증, 멱등성, 서버 금액 재계산, 트랜잭션, 관리자 인증 및 세션, 보안/로그. 프런트와 API 계약을 OpenAPI로 문서화.
7. **국내 결제**: 토스페이먼츠 등 PG의 요청→인증→서버 승인 구조를 별도 단계로 구현하고 주문번호·금액·승인키를 검증. 실제 결제 전까지 MOCK 환경이라는 사실을 UI/코드에 명시. 결제 승인 없는 주문은 판매 완료가 되면 안 됨.
8. **모션그래픽**: 타이포그래피 오프닝, 히어로 슬로우 페이드, 상품 카드 마이크로인터랙션, 스크롤 리빌, 모달·바텀시트·토스트. 브랜드 질감에 맞춰 효과를 절제하고 `prefers-reduced-motion`을 지킬 것. 사운드는 기본 비활성.
9. **이미지**: 기존 SVG는 시드 더미로 사용. 실제 사업/운영용 이미지는 이용권한을 확인하고 에셋 라이브러리에 저장. 이미지 최적화, 가변 사이즈, lazy-loading 적용.
10. **접근성 & 성능**: 대비, 키보드 동작, 초점 이동, aria-live, 명확한 탭 상태, 44px 이상 터치 타깃, CLS/LCP/INP 개선. 수평 스크롤 회귀 및 Hydration 오류 자동검사.

## 검증 지시
- 모드: 현재 파일들을 읽고 작업 단위를 PLAN→IMPLEMENT→TEST→SCREENSHOT QA→REPORT 순서로 실행.
- 각 페이즈는 스키마/라우트/컴포넌트 변경 목록, 사전·사후 결과, 스크린샷, 오류 재현 방법을 기록.
- Vitest/Node test + Playwright 모바일 E2E, 관리자 인증·구매/렌탈 재고 충돌·달력 날짜 계산·반납 후 세탁 상태를 테스트.
- `npm install`, `npm run test:api`, `npm run build` 통과 후 Chrome 모바일 375/390/430 및 데스크톱 검수.
- 임의로 기존 기능을 삭제하거나 외부 유료 API 키를 하드코딩하지 마세요.
- 작업 후 git status/diff 검수, 의미 있는 커밋 작성(저장소가 연결되어 있고 접근 권한이 있는 경우에만).

## 분석용 ZIP 정책
- 메인 애플리케이션 루트에 분석용 대용량 ZIP을 쌓지 않음.
- `/analysis-artifacts/<PHASE_ID>/`에 소스목록·구조요약·API문서·QA로그·스크린샷·변경파일목록을 저장.
- 각 페이즈마다 독립된 `<PHASE_ID>_ANALYSIS.zip`을 해당 폴더 안에 생성. `node_modules`, `.next`, `dist`, `.git`, 시크릿, 고객정보, 바이너리 대용량 원본은 제외.
- 필요 시 `analysis-artifacts/`는 `.gitignore`로 제외하고 결과 요약만 커밋. 업로드 공유용 요약 파일만 생성.

## 작업 순서
M1 기술분석/백업/디자인 토큰 → M2 고객 모바일 흐름 → M3 ERP 실물/예약 트랜잭션 → M4 결제/정산/회원 보안 → M5 에디토리얼 CMS·로고 모션/스플래시 → M6 자동·시각 QA 및 성능 → M7 운영 배포 가이드.
